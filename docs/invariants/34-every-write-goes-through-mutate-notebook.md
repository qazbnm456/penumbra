# Invariant 34: Every write goes through mutate_notebook

**Every write to a notebook goes through `notebook.mutate_notebook`, which re-loads the file inside a per-notebook lock and applies a caller-supplied delta, never a snapshot read earlier.**

`save_notebook` writes the whole `Notebook`, so persisting an object read minutes ago silently destroys everything written in between. Two faults had to be fixed together: the stale snapshot and interleaved critical sections. A lock alone would not have helped, because the racing writes never overlapped at the moment of writing. Every mutating path now does its expensive work unlocked against a snapshot, then calls `mutate_notebook` with only the delta. `save_notebook` has exactly one caller, `mutate_notebook`, and application code that calls it directly is a bug. `extend_with_sources` was removed, because ingesting and appending in one call is exactly what forces a caller to hold a snapshot across ingestion.

- The lock is `fcntl.flock` on a sidecar file, `<base_dir>/.<slug>.json.lock`, not `fcntl.lockf`. `flock` attaches to the open file description, so one mechanism serialises two threads and two processes, while POSIX record locks are per process and two `uvicorn` threads would pass straight through each other. It is a sidecar because `load_or_create` legitimately runs for a notebook that does not exist yet. The lock is not reentrant, so nothing passed to `mutate_notebook` may call `mutate_notebook` or `save_notebook`. Without `fcntl` it falls back to a process-local `threading.Lock`, which is still correct for the single-process deployment invariant 23 describes.
- `api.py` calls it through `asyncio.to_thread` (the shared `_mutate_or_http`, which holds the one copy of invariant 27's error mapping plus `FileNotFoundError` to 404), because a `flock` held by a CLI invocation must not stall the event loop. It validates the id before the thread, because an invalid id and a missing note both raise `ValueError`, and catching them together would misreport one as the other.
- Reads take no lock. `os.replace` is atomic, so a reader sees a complete old or new file, never a torn one. `ask` verifies citations against the snapshot corpus, which is the text the model actually read; reading a turn back later is invariant 11's business.
- `cli._prepare` persists ingestion before the model runs and returns the notebook that `mutate_notebook` produced, not its own snapshot. `append_sources` numbers ids against the fresh notebook, so a corpus built from the earlier objects would make the model cite `s2` for a source stored as `s4`. The API's `ask` is not exposed to this, because its snapshot holds only sources already stored.
- `mutate_notebook` checks a `create=False` miss before taking the lock as well as inside it. Entering the lock creates its sidecar file, so without the early check every 404 would leave a zero-byte file behind. The check inside the lock is the one that makes it correct.

## Trace retention

`traces/{run_id}.jsonl` is the one artifact that can contain full ingested source text, served by an API with no authorization. `prune_traces` (`traces.py`) removes traces by age (`RN_TRACE_RETENTION_DAYS`, 7 days by default) and by count (`RN_MAX_TRACE_FILES`, 500), where `0` disables either sweep. It runs at startup and after every run.

- Two rules outrank both sweeps: a run id in the caller-supplied `protected` set (the keys of `_RUN_PROCESSES`) and any file younger than one hour. Deleting a live run's trace would break its stream and free a run id the exclusive-create gate (invariant 29) still relies on. The one-hour floor covers what `protected` cannot: the moment before registration, and a run that has just finished whose trace the answer on screen links to.
- `traces._is_ours` gates every deletion. `_TRACE_DIR` is a relative `Path("traces")` resolved against wherever the server started, and sibling projects write `.jsonl` traces too; age and `protected` decide when a file dies, not whose it is. A trace is ours if its first line carries `rlm_harness.trace`'s schema marker, or if it is empty (an abandoned reservation, which must stay collectable). `api._prune_traces` logs what it removes, because the only destructive operation here must not be silent.
- The count cap applies to prunable traces only, so it is a soft cap on the directory. Charging protected and recent files against it would let a burst of concurrent runs, a number a client can influence, force traces well within retention to be deleted early.
- `prune_traces` never raises, because housekeeping must not turn a completed, paid-for `ask` into a 500. The lifespan therefore reads the retention settings itself, and a malformed value refuses startup; otherwise a typo would silently mean "never prune" for files that hold source text. They are standalone readers, not `NotebookConfig` fields, for invariant 30's reason: a server with no model configured must still clean up after itself.
- `api._prune_traces` takes its snapshot of `_RUN_PROCESSES` on the event loop before handing off to a thread, or it would race the loop's own changes to that map.
- The CLI writes a trace only when asked, to a path the caller names (`--trace PATH`), and nothing prunes it. Pruning belongs to the server, and tracing by default would scatter `traces/` directories wherever the command ran and leave files holding source text that nobody collects. The flag lives on the shared `_add_source_and_notebook_args`, so every run-taking command gets it. A missing directory is created (`TraceRecorder.__enter__` calls `os.makedirs(..., exist_ok=True)`), so only an unwritable path fails, and it fails before the model call (invariant 19).

Notebook writes share the default thread pool with other short host work, so a lock held by an external process can delay writes for unrelated notebooks. Long host-side work (synthesis, fetching, OCR) runs on its own daemon threads and does not hold that pool. This affects availability only, on a trusted-network service. A merging write, a multi-worker story for the in-memory run maps and a retention policy for `notebooks/` itself are not attempted.
