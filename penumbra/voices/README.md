# Reference voices for the `chatterbox` TTS provider

Two ten-second WAV clips give an Audio Overview **two distinguishable hosts** when `PN_TTS_PROVIDER=chatterbox`. Chatterbox ships exactly one built-in voice (`conds.pt` in its checkpoint), and every other voice comes from cloning a reference clip. Giving both hosts the built-in voice would turn a two-host episode into a monologue in two halves.

The clips carry **timbre only**. Their words are never heard in an episode: the model reads them to learn how the voice sounds, then speaks whatever the script says, in whatever language the orbit uses.

## Where they came from

Both were **synthesised by Kokoro** (`hexgrad/Kokoro-82M`, Apache-2.0) from the voices `am_adam` and `af_heart`, with the script at the bottom of this file. Kokoro was this project's local provider before Chatterbox replaced it. **No person was recorded to make them**, and that is the point: cloning a real person's voice raises a consent question that a recording's licence does not answer, and this project is in no position to answer it for someone else.

**The chain is not spotless, so it is written down.** Kokoro's model card says its training data includes *"synthetic audio generated by closed TTS models from large providers"*. The provenance behind these clips therefore has three hops: closed TTS output, into Kokoro's training set, into these clips, into a Chatterbox clone. Every hop is permissively licensed as distributed, and no human voice is appropriated at any of them. But this project has already paid once for taking a licence chain on trust (the AGPL `pymupdf` dependency, invariant 7), so the chain is disclosed rather than left to be discovered.

If that chain is not acceptable for your deployment, set `PN_TTS_VOICE_HOST_A` and `PN_TTS_VOICE_HOST_B` to an **absolute path** to your own reference `.wav`, and these files are never read. The override is environment-only and deliberately unreachable from the settings page, because a path arriving through an endpoint every token holder can reach would be an arbitrary file read (invariants 26 and 41). Setting either one to `built-in` uses Chatterbox's own voice instead.

## Why ten seconds

`ChatterboxMultilingualTTS.DEC_COND_LEN` is `10 * 24000` samples and `ENC_COND_LEN` is `6 * 16000`, so beyond ten seconds only the speaker-embedding encoder reads anything. Longer clips would add wheel size and buy nothing.

## Regenerating them

This needs `kokoro` and `misaki[zh]`, which the project no longer depends on, so install them into a throwaway environment. The text is never heard; it says what the file is, so anyone who opens it knows at once.

```python
import wave, numpy as np, pathlib
from kokoro import KPipeline

TEXT = ("This is a reference recording for a synthetic podcast host. It carries the timbre of the "
        "voice and nothing else. No person was recorded to make it.")
OUT, SR = pathlib.Path("penumbra/voices"), 24000
pipeline = KPipeline(lang_code="a")
for name, voice in (("host_a.wav", "am_adam"), ("host_b.wav", "af_heart")):
    audio = np.concatenate([r.audio.numpy() for r in pipeline(TEXT, voice=voice)])[: SR * 10]
    with wave.open(str(OUT / name), "wb") as handle:
        handle.setnchannels(1)
        handle.setsampwidth(2)
        handle.setframerate(SR)
        handle.writeframes((audio * 32767).astype("<i2").tobytes())
```
